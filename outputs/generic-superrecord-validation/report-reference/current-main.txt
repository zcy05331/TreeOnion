009                                                  A BSTRACT
010
011            Merkle authentication-path private information retrieval (PIR) returns the sibling
012            at every non-root level while hiding the selected leaf. For a perfect binary tree,
013            a public permutation that swaps each pair of siblings turns those siblings into an
014            ancestor path in the permuted logical view. Authentication-path retrieval there-
015            fore reduces to a single prefix-compatible path query, and the encrypted index is
016            unchanged. Dyadic record layouts make cross-level query reuse efficient, but they
017
               waste plaintext capacity when one logical node does not occupy a power-of-two
               number of coefficients. We introduce a generic super-record layout that groups an
018
               arbitrary number h ≥ 1 of adjacent nodes in that view while preserving the path
019
               prefix. The key identity is
020
021                                               ⌊i/2k ⌋
                                             ⌊︃           ⌋︃ ⌊︃       ⌋︃
                                                                ⌊i/h⌋
022                                                         =            .
                                                     h            2k
023
024            One mixed-scale ciphertext then packs a one-hot selector for the high part of
025
               σ = ⌊i/h⌋ together with encrypted rows for every bit of σ. The same selectors
               drive level-specific plaintext folding and private residue rotation. In the registered-
026
               key client-hint model, the server expands this query once, selects and aligns one
027
               plaintext per level and plane, projects away competing residues, and pools the
028            results into same-ring response ciphertexts. The client reconstructs each super-
029            record and selects one lane; in the sibling-swapped view that lane contains the
030            original sibling. For 256-bit nodes, a degree-2048 ring with 12 payload bits per
031            coefficient admits h = 3, G = 64, and one plane, which fills every coefficient
032            exactly and so removes the 1.5× capacity loss of the one-plane single-node layout
033            without moving to several planes per node. Over the 24 levels of an authentica-
034            tion path in a 224 -leaf tree, the layout leaves 677 padded plaintext cells, a 0.19%
035            residual, and the whole path fits in one response ciphertext; the client decodes one
036
               three-lane super-record per level, zero-padded where a level does not fill its last
               bundle.

      1   I NTRODUCTION
040
041
      Private access to hierarchical data often requires several related records, not one item from a flat ar-
042   ray. A Merkle-tree query, for example, may need the sibling at every non-root level, all of them fixed
043   by one hidden leaf index. Equivalently, after a public sibling-swapping permutation, the same query
044   asks for the ancestor at every level in the swapped logical view. Running an independent PIR scan
045   per level discards the shared prefix structure of those indices. Existing path-oriented systems avoid
046   that repetition through ORAM bucket reuse or tree-specific batch layouts (Mayberry et al., 2014;
047   Cao et al., 2025); here we study the corresponding problem inside an RLWE selection pipeline.
048   The immediate obstacle is plaintext utilization. OnionPIR-style schemes favor power-of-two record
049   geometries because binary CMux selection, private monomial rotation, and coefficient projection
050   then share a simple bit decomposition (Mughees et al., 2021; Chen & Ren, 2025). A fixed-size
051   node rarely fills such a geometry exactly. Padding every node to the next dyadic coefficient width
052   increases the number of plaintexts scanned: for 256-bit nodes and 12 payload bits per coefficient
053   the smallest dyadic plane width that holds a complete node in one plane is 32, so a one-plane node
      spends 384 bits of capacity to carry 256 bits of payload and each level scan grows by a factor of 1.5.

055   break the cross-level prefix query on which the path-wide computation depends.

      The client can therefore encrypt one bundled index σ = ⌊i/h⌋. At level ℓ, high bits of σ select a
061
      plaintext, while a sliding low-bit window selects the super-record residue. One mixed-scale packed
062   ciphertext contains both the first-dimension one-hot value and all encrypted σ bits. The server
063   then applies first-dimension selection, most-significant-bit-first folding, private rotation, coefficient
064   projection, and residue-slot response pooling for every level and data plane.
065
      The core construction is parameterized by a public logical tree view and a public set of active levels.
066
      The ordinary ancestor view uses the original tree and all L+1 levels. A Merkle authentication query
067                                                                  auth

069   each position, not the encrypted prefix index or any online selection step.

089   2   R ELATED W ORK
090
091   Lattice-based single-server PIR. OnionPIR combines lattice encryption schemes through ex-
092   ternal products to reduce the response overhead of single-server PIR while retaining a practical
093   database scan (Mughees et al., 2021). Compressed-query PIR introduced the single-ciphertext
094   oblivious expansion pattern (Angel et al., 2018). OnionPIRv2 develops these ideas into an
095   implementation-oriented system with packed query expansion, a large first-dimension plaintext–
096   ciphertext matrix product, and RGSW selectors for the remaining binary dimensions (Chen & Ren,
097
      2025). Our construction uses these query and selection primitives but changes the indexed object
      and the database geometry. It replaces a separately encoded fixed record coordinate with one en-
098
      crypted decomposition of σ = ⌊i/h⌋, whose different bit windows control plaintext folding and
099
      record alignment at every tree level.
100
101
      Coefficient projection and response packing. Respire targets PIR databases with small records
102   and develops query compression and response packing from ring-switching techniques (Burton
103   et al., 2024). Its coefficient projection zeroes coefficients outside a power-of-two stride by recur-
104   sively applying odd ring automorphisms; its Lemma A.6 gives the recurrence we use in Eq. (29).
105   The construction here uses that projection after a private monomial shift, then assigns projected
106   level-plane items to distinct residue classes of a shared response pool. It keeps the response in the
107   original ring. Respire’s subsequent dimension-reduction mechanism is therefore not part of the path
      protocol specified here.


                                                         2
108
      Private retrieval over trees. Path-PIR combines ORAM and PIR and, in its latency-optimized
109   variant, reuses one PIR vector for every bucket on a root-to-leaf ORAM path (Mayberry et al.,
110   2014). That reuse selects a fixed bucket position; our shared query instead exposes different prefix
111   and sliding-residue windows at different levels. TreePIR targets private Merkle-proof retrieval. It
112   first swaps every sibling pair so an authentication path in the original tree becomes a root-to-leaf
113   path in the public logical view, then applies balanced ancestral coloring and batch PIR (Cao et al.,
114   2025). We use the same public permutation but replace coloring and parallel batch queries with one
115   RLWE selection pipeline: an arbitrary-h super-record layout, one encrypted σ, private alignment
116   and projection, and pooled responses. Our authentication-path object is the one specified in RFC
117
      8391 and RFC 9162 (Huelsing et al., 2018; Laurie et al., 2021).

119   3     G ENERIC S UPER -R ECORD M ERKLE AUTHENTICATION -PATH PIR
120
121   The protocol replaces a padded single-node record with a level-local bundle of adjacent nodes. Its
122   central design choice is to query a global super-record index rather than to preserve a fixed record
123   position across levels. This choice supports arbitrary bundle arity, retains one packed query for the
124
      full path whenever Wmin ≤ n, and gives every level an explicit plaintext prefix and residue window.
      Figure 2 summarizes the complete offline and online data flow.

      3.8   L IMITATIONS
506
507   The sibling-swapped reduction and the level plan assume a perfect binary tree; RFC 9162-style non-
508   perfect history trees require a different public view and indexing argument. The database is public,
509   and the client learns one complete h-entry super-record per active level before local lane selection;
510   the response therefore carries hE bits per level for E useful bits. The client-hint deployment stores
511   per-client evaluation material at the server, so queries remain linkable to that registration even though
512   their indices are hidden. Both modes treated here contain level L, and m and N0 are planned for that
513
      level; an active-level set whose deepest level is shallower would leave the query over-provisioned.
      Concrete parameters must satisfy Eq. (35), and the layout counts alone do not imply a runtime
514
      improvement. Per-query evaluation-key delivery and degree-reducing response compression require
515
      separate protocol extensions.

518   4     C ONCLUSION
519
520   We developed a prefix-compatible super-record layout for private Merkle authentication paths in
521   perfect binary trees. A public sibling swap turns the required proof nodes into logical path positions,
522
      while ⌊⌊i/2k ⌋/h⌋ = ⌊⌊i/h⌋/2k ⌋ lets one encrypted bundled index drive every level for arbitrary
      h. We specify mixed query packing, bounded level matrices, private alignment, projection, and
523
      response pooling, with separate exact-phase, noise, and privacy statements. Bundle3 adds only
524
      0.19% matrix padding for 256-bit nodes. Implementation, concrete noise validation, non-perfect
525   history trees, and end-to-end measurement remain future work, as does a fair comparison against
526   both the current one-plane implementation and the best multi-plane h = 1 candidate.
