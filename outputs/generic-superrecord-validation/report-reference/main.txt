009                                                  A BSTRACT
010
011            Merkle authentication-path private information retrieval (PIR) returns the sibling
012            at every non-root level while hiding the selected leaf. For a perfect binary tree,
013            a public permutation that swaps each pair of siblings turns this object into an an-
014            cestor path in the permuted logical view. We therefore reduce authentication-path
015            retrieval to one prefix-compatible path query, without changing its encrypted in-
016            dex. Dyadic record layouts make cross-level query reuse efficient, but they waste
017
               plaintext capacity when one logical node does not occupy a power-of-two number
               of coefficients. We introduce a generic super-record layout that groups any posi-
018
               tive integer h of adjacent public nodes while preserving the path prefix. The key
019
               identity is
020
021                                               ⌊i/2k ⌋
                                             ⌊︃           ⌋︃ ⌊︃       ⌋︃
                                                                ⌊i/h⌋
022                                                         =            .
                                                     h            2k
023
024
               One mixed-scale ciphertext then packs a one-hot selector for the high part of
               σ = ⌊i/h⌋ together with encrypted rows for every bit of σ. The same selectors
025
               drive level-specific plaintext folding and private residue rotation. In the registered-
026
               key client-hint model, the server expands this query once, selects and aligns one
027            plaintext per level and plane, projects away competing residues, and pools the
028            results into same-ring response ciphertexts. The client reconstructs each super-
029            record and selects one lane; in the sibling-swapped view that lane contains the
030            original sibling. For 256-bit nodes, a degree-2048 ring with 12 payload bits per
031            coefficient admits h = 3, G = 64, and one plane. Across all 25 levels of a 224 -leaf
032            tree, the layout adds only 677 plaintext cells (0.19%); its 24-node authentication
033            path fits in one response ciphertext.

      1   I NTRODUCTION
037
      Private access to hierarchical data often requires several related records, not one item from a flat
038
      array. A Merkle-tree query, for example, may need the sibling at every non-root level while revealing
039
      only a leaf index. Equivalently, after a public sibling-swapping permutation, the same query asks
040   for the ancestor at every level in the swapped logical view. Running an independent PIR scan per
041   level discards the shared prefix structure of those indices. Existing path-oriented systems avoid that
042   repetition through ORAM bucket reuse or tree-specific batch layouts (Mayberry et al., 2014; Cao
043   et al., 2025); here we study the corresponding problem inside an RLWE selection pipeline.
044
      The immediate obstacle is plaintext utilization. OnionPIR-style schemes favor power-of-two record
045
      geometries because binary CMux selection, private monomial rotation, and coefficient projection
046   then share a simple bit decomposition (Mughees et al., 2021; Chen & Ren, 2025). A fixed-size
047   node rarely fills such a geometry exactly. Padding every node to the next dyadic coefficient width
048   increases the number of plaintexts scanned. Grouping h adjacent nodes into a super-record can
049   remove that loss, but an arbitrary h appears to break the cross-level prefix query on which the path-
050   wide computation depends.
051
      Our key observation is that grouping commutes with ancestor truncation:
052
                                              ⌊i/2k ⌋
                                           ⌊︃         ⌋︃ ⌊︃       ⌋︃
053                                                         ⌊i/h⌋
                                                        =            .
                                                 h            2k

      The client can therefore encrypt one bundled index σ = ⌊i/h⌋. At level ℓ, high bits of σ select a
055   plaintext, while a sliding low-bit window selects the super-record residue. One mixed-scale packed
056   ciphertext contains both the first-dimension one-hot value and all encrypted σ bits. The server
057   then applies first-dimension selection, most-significant-bit-first folding, private rotation, coefficient
058   projection, and residue-slot response pooling for every level and data plane.
059
      The core construction retrieves path positions from a public logical tree view and a public set of
060
      active levels. The ordinary ancestor view uses the original tree and all L + 1 levels. A Merkle
061                                                                                       auth
      authentication query instead uses levels 1, . . . , L of the sibling-swapped view Vℓ,j   = Mℓ,j⊕1 . At
062   logical position jℓ , this view stores the original sibling Mℓ,jℓ ⊕1 . The public permutation changes
063   what is encoded at each position, not the encrypted prefix index or any online selection step.
064
065
      Our contributions are:
066
             • We reduce Merkle authentication-path PIR on perfect binary trees to path retrieval over a
067            public sibling-swapped view, then develop an arbitrary-h, multi-plane super-record layout
068            for that view.
069
             • We specify a registered-key protocol, also called a client-hint model, whose online request
070
               is one mixed BFV/RLWE-star ciphertext, with explicit setup, preprocessing, expansion,
071            conversion, and projection key inputs and a scale-correct packing algorithm.
072
             • We prove the prefix, matrix-cover, selector-range, projection, and response-placement in-
073
               variants, and separate exact-phase correctness, noise-conditioned correctness, and condi-
074
               tional non-adaptive query privacy.

076
             • For 256-bit nodes, the Bundle3 specialization uses one plane and leaves only 677 padded
               matrix cells out of 349,540 logical plaintexts, a 0.19% structural overhead.

      2   R ELATED W ORK
083
084
      Lattice-based single-server PIR. OnionPIR combines lattice encryption schemes and external
      products to reduce the response overhead of single-server PIR while retaining a practical database
085
      scan (Mughees et al., 2021). Compressed-query PIR introduced the single-ciphertext oblivious ex-
086
      pansion pattern (Angel et al., 2018). OnionPIRv2 develops these ideas into an implementation-
087   oriented system with packed query expansion, a large first-dimension plaintext–ciphertext matrix
088   product, and RGSW selectors for the remaining binary dimensions (Chen & Ren, 2025). Our con-
089   struction uses these query and selection primitives but changes the indexed object and the database
090   geometry. It replaces a separately encoded fixed record coordinate with one encrypted decomposi-
091   tion of σ = ⌊i/h⌋, whose different bit windows control plaintext folding and record alignment at
092   every tree level.
093
094   Coefficient projection and response packing. Respire targets PIR databases with small records
095   and develops query compression and response packing from ring-switching techniques (Burton
096   et al., 2024). Its coefficient projection zeroes coefficients outside a power-of-two stride by recur-
097
      sively applying odd ring automorphisms; Lemma A.6 gives the recurrence used in Eq. (27). The
      construction here uses that projection after a private monomial shift, then assigns projected level-
098
      plane items to distinct residue classes of a shared response pool. It keeps the response in the original
099
      ring. Respire’s subsequent dimension-reduction mechanism is therefore not part of the path protocol
100   specified here.
101
102   Private retrieval over trees. Path-PIR combines ORAM and PIR and, in its latency-optimized
103   variant, reuses one PIR vector for every bucket on a root-to-leaf ORAM path (Mayberry et al.,
104   2014). That reuse selects a fixed bucket position; our shared query instead exposes different prefix
105   and sliding-residue windows at different levels. TreePIR targets private Merkle-proof retrieval. It
106   first swaps every sibling pair so an authentication path in the original tree becomes a root-to-leaf
107   path in the public logical view, then applies balanced ancestral coloring and batch PIR (Cao et al.,
      2025). We use the same public permutation but replace coloring and parallel batch queries with one

      RLWE selection pipeline: an arbitrary-h super-record layout, one encrypted σ, private alignment
109   and projection, and pooled responses. The authentication-path object follows RFC 8391 and RFC
110   9162 (Huelsing et al., 2018; Laurie et al., 2021).

117
      full path whenever W ≤ n, and gives every level an explicit plaintext prefix and residue window.

532
533   The sibling-swapped reduction and the level plan assume a perfect binary tree; RFC 9162-style non-
534
      perfect history trees require a different public view and indexing argument. The database is public,
      and the client learns one complete h-entry super-record per active level before local lane selection.
535
      The client-hint deployment stores per-client evaluation material at the server, so queries remain
536
      linkable to that registration even though their indices are hidden. Concrete parameters must satisfy
537   Eq. (33), and the layout counts alone imply no runtime improvement. Per-query evaluation-key
538   delivery and degree-reducing response compression require separate protocol extensions.

      4   C ONCLUSION
541
542
      We formulated a prefix-compatible super-record layout for private retrieval of Merkle authentication
543   paths in perfect binary trees. A public sibling-swapped view turns the required siblings into logical
544   path positions, while the identity ⌊⌊i/2k ⌋/h⌋ = ⌊⌊i/h⌋/2k ⌋ lets one encrypted bundled index drive
545   every level even when h is not dyadic. The resulting protocol defines scale-correct mixed query
546   packing, bounded level matrices, private residue alignment, coefficient projection, pooled responses,
547   and client-local lane extraction. Its exact-phase theorem proves path retrieval in the logical view
548   supplied to preprocessing, and the public sibling-swapped view turns the same protocol into Merkle
549   authentication-path retrieval for perfect binary trees. The noise and privacy statements expose the
550   cryptographic assumptions required to realize that algebra. Bundle3 shows that the layout can nearly
551
      eliminate matrix padding for 256-bit nodes. Implementing the generic layout, validating its noise
      margins, extending the view transform to non-perfect RFC 9162-style history trees, and measuring
552
      end-to-end runtime are the next evidence needed.
